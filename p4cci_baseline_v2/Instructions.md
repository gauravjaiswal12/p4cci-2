# P4CCI Full Implementation: Instructions

> *P4CCI: P4-Based Online TCP Congestion Control Algorithm Identification for Traffic Separation*

---

## Project Structure

```
p4cci_baseline_v2/
├── p4cci_switch.p4        # P4-16 data plane: BIF computation + 3-queue egress steering
├── controller.py          # Control plane: MAD -> Z-norm -> FCN classify
├── fcn_model.py           # 1D FCN (128->256->128, L=20) with train/save/load/infer
├── fcn_model.pth          # Trained FCN model weights (generated by fcn_model.py)
├── generate_dataset.py    # Synthetic BIF dataset generator (CUBIC/Reno/BBR)
├── topology_4flow.py      # Dumbbell topology: 4 senders -> 1 switch -> 4 receivers
├── topology_cross.py      # Cross topology: 8 senders -> 4 switches -> 4 receivers
├── evaluate.py            # Standalone JFI / link utilization / deviation evaluator
├── collect_metrics.py     # Per-run metric collector (KBCS-compatible CSV format)
├── test_suite_p4cci.sh    # 30-run statistical test suite (dual topology + dual mode)
├── verify_metrics.py      # Cross-module consistency checker
├── build/
│   └── p4cci_switch.json  # Compiled BMv2 JSON (generated by p4c)
├── results/               # CSV output directory
└── logs/                  # Per-run iperf log directory
```

---

## 1. Prerequisites

```bash
sudo apt-get update && sudo apt-get install -y iperf
# For FCN classifier (recommended):
pip install torch numpy
```

---

## 2. Compile the P4 Program

```bash
cd ~/p4cci_baseline_v2
mkdir -p build
p4c --target bmv2 --arch v1model p4cci_switch.p4 -o build/
```

Expected output: `build/p4cci_switch.json`

---

## 3. Train the FCN Classifier

```bash
# Generate synthetic BIF dataset + train FCN (takes ~10 seconds)
python3 fcn_model.py
# Saves: fcn_model.pth
```

The controller auto-loads `fcn_model.pth` if it exists, otherwise falls back to CV heuristic.

---

## 4. Run Statistical Test Suite (30 runs)

### Cleanup first:
```bash
sudo mn -c
sudo killall simple_switch 2>/dev/null
```

### P4CCI mode (CCA-aware traffic separation):
```bash
# Dumbbell topology (4 flows)
sudo ./test_suite_p4cci.sh --topo dumbbell --mode p4cci --runs 30

# Cross topology (8 flows)
sudo ./test_suite_p4cci.sh --topo cross --mode p4cci --runs 30
```

### Baseline mode (no separation, pure FIFO):
```bash
# Dumbbell topology
sudo ./test_suite_p4cci.sh --topo dumbbell --mode baseline --runs 30

# Cross topology
sudo ./test_suite_p4cci.sh --topo cross --mode baseline --runs 30
```

### Quick test (3 runs, 30s each):
```bash
sudo ./test_suite_p4cci.sh --topo dumbbell --mode p4cci --runs 3 --duration 30
```

## 7. Topologies

### Dumbbell (4 flows, 1 switch)
```
h1 (CUBIC)   --+                      +-- h5 (Receiver)
h2 (BBR)     --+-- [S1: P4Switch] ----+-- h6 (Receiver)
h3 (VEGAS)   --+                      +-- h7 (Receiver)
h4 (ILLINOIS)--+                      +-- h8 (Receiver)

Bottleneck: 250 pps (~3 Mbps) on egress ports 5-8
```

### Cross (8 flows, 4 switches)
```
h1-h4 --+-- S1 --+-- S3 --+-- h9, h10
         |         X       |
h5-h8 --+-- S2 --+-- S4 --+-- h11, h12

Bottleneck: 250 pps (~3 Mbps) on S1-S3, S1-S4, S2-S3, S2-S4
Total capacity: 6 Mbps per ingress switch
```

## 8. Expected Results (from paper)

| Metric | Baseline (FIFO) | P4CCI (With Sep.) |
|--------|-----------------|-------------------|
| Jain Fairness Index | ~0.70 | ~0.90+ |
| Link Utilization | ~70-80% | ~95%+ |
| Throughput Deviation | High (~0.50) | Low (~0.03) |

## 9. CCA Classification

| CCA | Class | Queue |
|-----|-------|-------|
| CUBIC | Loss-based (1) | Q1 |
| Reno | Loss-based (1) | Q1 |
| Vegas | Loss-based (1) | Q1 |
| Illinois | Loss-based (1) | Q1 |
| BBR | Model-based (2) | Q2 |

Per paper Section III-F: Only 2 classes (Loss-based and Model-based/BBR).

## 10. Classifier Modes

| Mode | Condition | Accuracy |
|------|-----------|----------|
| FCN (paper) | PyTorch + fcn_model.pth | ~99% (synthetic) |
| CV Heuristic | Fallback (no torch/model) | ~90% (synthetic) |

The controller auto-selects FCN if the trained model file exists.
